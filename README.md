# layout-viewer

一个基于 KLayout 实现的版图（GDS/OAS）查看工具。

## 插件化架构

**[Situation]** 本工具的功能模块（ruler、select、goto 等）都需要与主窗口（mainwindow）、资源树（tree）、画布（LayoutView）交互。以 ruler 为例：常规做法是在画布的鼠标事件处理里直接创建ruler对象并绘制，由此带来三个问题：
- 画布只负责显示，却承担了创建ruler的职责——违背了单一职责原则
- 新增一种标尺相关功能都要修改画布，而修改画布又可能弄坏标尺等既有功能——违背了开闭原则
- 画布（高层模块）直接调用标尺模块（底层模块）的具体函数，而非抽象——违背了依赖倒置原则
功能越多，耦合的维护成本越高。

**[Task]** 引入插件化架构，把具体功能模块与主程序解耦，让主程序只依赖抽象。

**[Action]** 以 ruler 功能为例，插件负责标尺对象的创建与管理，并与主窗口、画布、资源树交互。
- **插件注册**：插件以静态注册的方式登记到注册中心——在链接时自动完成注册，因此增删插件时主流程零改动；注册对象同时接管插件的生命周期（插件的登记、注销与释放）。
- **主界面交互**：主窗口初始化时遍历注册中心，装配菜单与工具栏；设置对话框同样遍历注册中心，收集各插件的配置页；mainwindow只依赖声明的抽象接口，代码中不出现任何具体插件（依赖倒置）。
- **画布交互**：LayoutView 初始化时遍历注册中心，为每个插件创建属于该视图服务对象；鼠标事件到来时，画布进行事件分发，交由各个插件画布服务处理。画布既不创建、也不认识任何具体插件。
- **资源树交互**：插件持有资源树指针，在标尺数据变化时把最新列表同步给树，由树刷新对应条目；

**[Result]** 新增功能只需实现插件声明与相应组件，主程序零改动；不参与链接的插件，相关内容全部消失
